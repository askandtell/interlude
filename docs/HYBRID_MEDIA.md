# 直连优先，必要时转发

新房间默认自动选路。统计的是已批准且在线的成员，包括房主；待审批和离线成员不占直连人数。

| 条件 | 行为 |
| --- | --- |
| 1—3 人在线 | 原生 WebRTC 点对点连接，不申请 LiveKit 凭证 |
| 第 4 人上线 | 全房间迁移到 LiveKit，之后最多 8 人 |
| 建连 12 秒失败、连接失败、断线超过 6 秒 | 全房间切换到 LiveKit |
| 放映中观看端超过 12 秒没有新解码画面 | 尝试转发，暂停和等待房主不触发此判断 |
| 多人转发后减少到 3 人以内 | 切换至少 30 秒后，在暂停时回到直连 |
| 直连失败后的转发 | 保持转发；房主可暂停后点击“重试直连” |
| 房主需要诊断网络或避免向成员暴露直连地址 | 点击“改用转发” |

直连发送的是正在播放的实时画面和声音，观看端不需要先下载完整电影。房主给每个观看者分别上传一路，因此三人时房主约需承担两路电影的上传。字幕仍在房主合成；语音使用独立的音轨与音量。观看者之间只建立语音连接。

自动切换保留已选文件和时间线，先暂停、关闭旧连接，再重新发布。之前已经点击观看的人会重新连接；正在放映时可恢复，之前已暂停则保持暂停。麦克风不会随切换自动打开。浏览器如果阻止播放，仍需本人点击恢复。切换期间会有短暂中断。

## 免费与隐私边界

直连不连接 LiveKit、不占 LiveKit 参与者分钟或电影下行额度；房间管理与聊天仍经过控制服务。使用 Cloudflare 公共 STUN `stun:stun.cloudflare.com:3478` 协助发现网络地址，STUN 不转发电影，也不配置付费 TURN。运营方和网络可能限制其可用性。参考 [官方 STUN 说明](https://developers.cloudflare.com/realtime/turn/faq/)。

点对点通信可能向已经批准的朋友暴露你的公网网络地址。不要将它理解为匿名网络；介意这一点时房主应在开始前改用转发。媒体使用浏览器 WebRTC 传输加密，不额外宣称实现了应用级端到端加密。

跨运营商、严格 NAT、UDP 被阻断等情况下可能无法直连。此时仍依赖 LiveKit 的剩余免费额度。软件不购买资源、不切换付费套餐，但没有实现账单级免费额度预留或硬限额；必须在托管商保持免费套餐且不绑定支付方式。额度耗尽或控制服务休眠时无法保证观看可用。

## 权限与清理

所有信令经过已有同源 Socket.IO 会话，并在房间锁内检查成员审批、目标房间、媒体代次和连接代次。每次加入媒体生成新的随机 nonce；过期连接的 SDP/ICE 不能进入新连接。消息有大小、结构、候选队列和频率限制，不存储 SDP、ICE 或电影。一个成员身份同时只能开启一个直连媒体页面。

换片、移除成员、转交房主、结束、代次变化时关闭旧连接；旧画面不能继续被新发布复用。控制断开暂停房主并关闭麦克风，恢复后不自动重新打开。LiveKit 路径仍使用短时最小权限凭证及旧媒体房间清理。
