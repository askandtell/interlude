# 界面与交互实现

## 视觉与页面

采用 C 版方案：暖白入口、石墨黑放映室、纯黑银幕，少量琥珀色。系统无衬线字体、主要操作至少 44px、正文以 14–16px 为主。只保留短促状态过渡，遵循减少动态效果设置。产品不再加载装饰性图片、Three.js 或 GSAP。

首页只有创建房间、完整邀请链接、本机最近记录。加入页区分读取中、昵称、等待批准、申请拒绝和房间结束，不展示虚构的公共片库或账户。放映页是紧凑顶栏、大银幕、统一控制条和 320px 聊天栏；手机使用底部抽屉，横屏压缩控制区。全屏容器包含银幕与控制条，弹出的字幕设置也保留在全屏 DOM 内。

## 客户端职责

- `useRoomSession`：认证后的房间快照、控制连接、HTTP 管理与 Socket 命令。命令错误向调用方抛出；连接恢复取得快照后再解锁操作。
- `useLocalFilm`：候选文件检测／兼容处理／提交／就绪／失败、过期任务取消、确认续播和共享字幕设置。
- `usePlaybackConnection`：独立媒体连接、真实接收画面、播放受阻、语音轨状态和资源清理。
- `useDeviceTest`：用户主动触发的本地麦克风、电平、测试音。测试不申请媒体凭证，关闭弹窗停止临时音轨；权限请求晚返回时也立即释放。

没有新增服务器业务接口。服务端仍负责角色、准入、播放顺序和媒体代次。界面中的播放时间是权威时间线的估算，不是渲染时延测量；不会展示虚构的延迟数字。

## 关键状态与恢复

检测候选文件前暂停原片，原资源保持有效。候选准备完成并获得服务端确认后，才停止旧发布并替换。取消、读取失败或服务端拒绝不会显示新影片已就绪；取消后的迟到结果不得提交。提交中的切换不可再取消，防止服务端与本地状态分叉。

刷新后明确要求重新选择文件。标签页最多保留四个房间的文件名、大小、修改时间、时长及观看位置，24 小时内的匹配可以提出续播；用户确认后只跳转、不自动播放。元数据匹配不等于内容哈希验证，也不能恢复文件权限。

控制断线时房主暂停，仍可用的媒体连接不立即销毁。恢复后保持暂停，等待明确操作。媒体断线、等待画面与播放受阻分别显示，提供连接重试或播放恢复。角色、媒体代次、撤销或房间结束变化会取消旧连接和本地任务。

## 字幕、设备与无障碍

SRT/VTT 保持有界纯文本解析。字号 80%／100%／120%，时间偏移 ±10 秒、0.1 秒步长，正数表示延后；长行按实际字体测量换行，最多三行并截断。房主直接预览同一张合成画布，观看者接收该画布视频，避免两套字幕排版不一致。

电影和语音音量独立；窄屏可从设置调整电影音量。麦克风默认关闭，设备检测需主动点击，测试不回放麦克风以避免啸叫。设备列表与输出选择按浏览器能力和权限显示；不支持时提示使用系统声音设置。音频设备标识只保存在本机，不进入房间事件或日志。

滑块具有可读名称和键盘操作；进度在等待服务端确认期间保留拖动草稿，避免快速方向键被后台时间刷新覆盖。输入框、按钮、滑块与弹窗内不触发全局空格播放。可见焦点、抽屉焦点约束和减少动态效果已有浏览器检查，完整人工读屏及真实移动端仍独立验收。
