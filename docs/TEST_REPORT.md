# 测试结果

测试日期：2026-10-16。本文只记录“各自播放，一起观看”版本，旧版视频转发结果不适用于当前版本。

## 本机检查

环境为 Windows、Node.js 24 和桌面 Chromium。独立浏览器上下文模拟不同成员，不代表多台实体设备。

- TypeScript、生产构建、格式检查通过。
- 46 项单元及服务测试通过，覆盖会话、CSRF、权限、邀请、限流、来源代次、成员状态、旧房间迁移、真实 WebSocket 握手与校时。2 项真实 Redis 测试未在本次本机运行中执行。
- 14 项浏览器测试通过，覆盖邀请、审批、拒绝、聊天、全屏审批、刷新、两人及八人各自播放、暂停、跳转、移除、时长不匹配、损坏文件保留旧片、个人字幕、手机尺寸布局、控制重连及入口加载失败后的重试。
- 网站模式使用受控测试播放器验证暂停、跳转、来源变化和连接超时。四个平台的真实登录、广告、会员播放尚未完成实测，仍标为实验性。
- npm 官方 registry 的运行依赖审计未报告漏洞。审计不能证明不存在安全问题。

测试片由 FFmpeg 生成，包含带画面帧号的 H.264/AAC MP4、WebM、MKV 和无音轨样例。样例齐备不等于所有格式都已完成浏览器实测；编码支持仍以设备预检结果为准。

## 同步测量

`tests/e2e/together.spec.ts` 从实际解码画面读取帧号，按 30fps 计算两个成员的差异。最近一次 20 次采样的 P95 为 66.7ms，目标上限为 500ms。八人测试另外确认每个成员独立解码和响应暂停，没有测量八人所有组合的 P95。

测试还拦截房主页面的 RTCPeerConnection 和 getUserMedia，确认没有创建音视频连接、请求麦克风或调用媒体凭证接口。应用依赖和服务端中已移除媒体 SDK。

原始结果保存在本机忽略目录 `artifacts/together-sync.json`，截图见 `docs/design/`。这些本机数值不能用作公网性能承诺。

## 公网与未覆盖环境

现有体验站：<https://interlude-eoqk.onrender.com>。已上线新的同步协议，健康检查确认 Redis 可用。GitHub Linux CI 已通过类型、构建、单元测试、审计和浏览器检查。

公网运行中，侧栏收起时的审批、手机尺寸审批、多人申请与刷新、两人实际解码及暂停/跳转/移除、控制重连通过；两人画面差异 P95 为 100ms，未创建音视频连接。同一台电脑使用同一条网络，不代表跨运营商测试。

整轮公网检查为 5 项通过、5 项未通过。失败包括新页面空白、连接关闭、播放组件下载失败，以及测试在成员控制连接完成前选片。后者已改为等待实际可操作状态；新增加载失败提示与刷新入口。公网八人、字幕及其余失败场景仍需补验，不能把本机通过当作这些场景已上线验收。

以下仍待验收：不同运营商及弱网、真实 iOS/Android、完整读屏、两小时连续播放与内存增长、自动播放权限组合、快速取消与连续兼容转换、各网站真实广告及会员播放。桌面浏览器的手机尺寸检查只验证布局。

## 隐私与密钥

`npm run security:secrets` 检查误跟踪的私密配置、常见凭证格式、前端秘密引用以及本机凭证是否被复制到源码和构建。Gitleaks 用于发布差异检查，报告使用脱敏输出。

此前完整历史检查发现 15 条上游历史告警，来自引入 WatchParty 前已有的旧配置、标识及测试私钥。当前应用不使用这些配置，未尝试验证旧凭证；上游历史保留。不能把删除当前文件当成撤销已泄露凭证。

## 复现

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:media
npm run test:e2e
```

生成样例需要 FFmpeg。重复运行触发本机每小时创建限额时，重新启动本机开发控制服务；不要为测试放宽生产限流。

公网测试仅针对自己有权测试的实例：

```powershell
$env:PUBLIC_E2E_URL='https://你的服务.onrender.com'
npm run test:public
```

测试会创建临时房间并发送少量控制消息，不上传影片或使用云端音视频额度。未配置地址时不会访问公网。
