## 同步测量

测试片在画面中编码帧号，以 30fps 计算已显示画面的差异，测试代码在 `tests/e2e/cinema.spec.ts` 和 `tests/e2e/hybrid.spec.ts`。

- 本机转发：房主与一个观看者，P95 为 100ms。
- 本机直连：房主与两个观看者，20 次采样的最大画面差 P95 为 66.7ms。

以上结果来自同一台 Windows 电脑上的独立 Chromium 上下文。本地测试目标是 500ms，不能将这些数值作为公网性能承诺。原始运行结果位于本机忽略目录 `artifacts/`；运行测试可重新生成。

## 公网实例

地址：<https://interlude-eoqk.onrender.com>。

`tests/e2e/public.spec.ts` 检查实际解码帧持续增长、电影音轨 RMS、语音轨、暂停和移除成员。会话 Cookie 检查包含 Secure、HttpOnly、SameSite=Strict。测试房间完成后关闭。

两个浏览器使用同一条本地网络，因此这不是不同运营商测试。直连可能使用本机候选地址；转发测试使用实际 LiveKit Cloud，没有用本机媒体服务替代。测试输出见 `artifacts/public-direct.json`、`artifacts/public-relay.json` 及对应截图。

准入回归还覆盖了侧栏收起、手机布局、多人排队、房主刷新、连接建立前拒绝申请，以及全屏中查看申请。五种场景均已在公网实例完成验证。测试期间曾因本机浏览器下载脚本时出现 `ERR_SSL_PROTOCOL_ERROR` 而超时；改用 HTTP/1.1 后补测通过。该结果不代表不同网络下都能稳定访问。

最近一次音画补测中，直连的画面、电影声音、语音、暂停和移除成员全部通过。转发测试在页面加载或控制连接阶段遇到连接关闭，未完成这次回归；前面记录的云端转发通过结果来自较早的运行。

## 如何复现

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
```

安装 FFmpeg 后，运行 `npm run test:media` 生成测试片和固定麦克风测试音。Linux CI 使用 PulseAudio 提供音频输出时钟。测试原生转发时，先启动 LiveKit，再设置 `MEDIA_E2E=1`。

公网测试需要明确指定自己有权测试的实例：

```powershell
$env:PUBLIC_E2E_URL='https://你的服务.onrender.com'
npm run test:public
```

公网测试会创建临时房间并使用少量媒体额度。未配置地址时，默认测试不会访问公网实例。
