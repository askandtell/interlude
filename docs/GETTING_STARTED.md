# 第一次使用幕间

幕间是浏览器里的好友私人放映室。它不提供影视资源，也不需要每位朋友注册 Render、LiveKit 或 GitHub。

## 选一条使用方式

| 你想做什么 | 需要准备什么 | 从哪里开始 |
| --- | --- | --- |
| 加入朋友的房间 | 朋友发来的完整邀请链接、浏览器 | 下方“加入朋友” |
| 在已有实例上放映 | 实例网址、桌面 Chrome/Edge、本地视频 | 下方“自己放映” |
| 在自己电脑上试用 | Node.js 24+、Git | 下方“本机试用” |
| 建立自己的分享网址 | 自己的 GitHub、Render、LiveKit 账号 | 下方“免费部署” |

**公开仓库提供软件源码，不包含维护者的云端账号或密钥。** 使用自己的部署实例消耗你自己的资源。维护者的体验实例可能休眠、限流或停止，不是面向所有人的无限量免费影视服务。

## 加入朋友

1. 用浏览器打开朋友发来的完整邀请链接，保留 `#invite=...` 部分。
2. 填昵称，申请加入，等待房主批准。
3. 点击“开始观看”。麦克风默认关闭，想说话时再手动开启。
4. 观看者可以调自己的电影与语音音量，暂停、跳转由房主控制。需要暂停时发送“等我一下”。

没有“房间码”，也没有公开房间列表。单独复制地址栏里的房间路径可能无法让新朋友进入；请让房主通过“邀请朋友”生成邀请。每次生成新邀请，之前的链接失效。

## 自己放映

1. 打开所用实例首页，创建房间并填写昵称。
2. 选择本地影片，等格式检测完成。失败时按具体提示转换或换片。
3. 点击“邀请朋友”复制链接，逐一批准熟悉的人。
4. 点击“开始放映”，保持当前页面打开。朋友各自点击“开始观看”。

建议先使用常见 MP4 H.264/AAC；这只是便于起步的样例，实际兼容性由内容检测决定。服务器不保存完整电影文件。房主刷新后需要重新选择文件并确认续播，文件不会自动交给新房主。

本地影片的放映端需要桌面 Chrome/Edge。Safari、Firefox 与手机观看以实际能力检测和测试为准，真实手机兼容矩阵尚未完整验收。自动播放被浏览器阻止时点击“恢复声音与画面”。

## 本机试用：不需要云账号

安装 Node.js 24+、Git，执行：

```sh
git clone https://github.com/askandtell/interlude.git
cd interlude
npm ci
node scripts/setup-dev.mjs
```

再分别打开两个终端，在项目目录运行：

```sh
npm run dev
```

```sh
npm run ui
```

访问 **http://127.0.0.1:15173**，不要换成 localhost。新房间可尝试 3 人以内 P2P，不启动 LiveKit 时没有云端转发兜底。未配置 Redis 时采用开发内存存储，重启后房间丢失。

需要本机测试转发时，安装 Docker 后执行 `npm run infra`，或者按[开发部署文档](DEPLOYMENT.md)启动原生 LiveKit。初始化脚本只生成本机随机配置，不覆盖已有 `.env`；不要把生成的密钥提交到 Git。

**localhost 链接只能在你的电脑使用。** 不要把它发给远处的朋友，也不要直接把开发端口暴露到公网。跨电脑试用请走 HTTPS 部署。

## 免费部署：使用自己的账号

这条路线不要求自购域名或 VPS，使用托管商二级域名和其当前允许的免费规格。是否提供免费规格及是否要求信用卡，以你的账号创建页面为准；要求付费时停止，软件没有自动代付能力。

1. Fork 此 GitHub 仓库。不要复制维护者的 `.env`、Render 环境变量或 LiveKit 项目。
2. 注册/登录自己的 LiveKit Cloud，选择免费 Build 项目。保存项目 WSS URL 和自己创建的 API key/secret，只用于服务端。
3. 登录自己的 Render，创建 Blueprint，选择 Fork 后的仓库与 `main` 分支，使用根目录 `render.yaml`。
4. 检查 Web Service 和 Key Value **都是 Free**；不添加磁盘、付费副本、付费套餐或支付方式。按表填写环境变量后部署。
5. 等待构建与健康检查成功。Render 提供 `https://你的服务.onrender.com`，不需要购买域名。
6. 在 LiveKit 的 Webhooks 中添加 `https://你的服务.onrender.com/api/livekit/webhook`，选择与应用环境变量对应的 API key 签名。
7. 用两个独立浏览器身份真实观看测试片，分别验证直连和“改用转发”，再分享给朋友。

| 变量 | 从哪里来 | 放在哪里 |
| --- | --- | --- |
| `LIVEKIT_URL` | 自己项目的 `wss://…livekit.cloud` | Render 服务端环境变量 |
| `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | 自己 LiveKit 项目的密钥 | Render 服务端秘密变量 |
| `SESSION_SECRET` | Blueprint 自动随机生成 | 服务端，勿手动复制别人的值 |
| `REDIS_URL` | Blueprint 内网 Key Value 自动连接 | 服务端，不对公网开放 |
| `APP_ORIGIN` | Render 默认不需要手动填 | 自动使用 `RENDER_EXTERNAL_URL`；自定义部署时填写准确 HTTPS Origin |

不要设置 `VITE_LIVEKIT_API_SECRET`，不要把任何 secret 放进前端构建变量、Issue、截图或 README。只有房间管理服务可以签发短时媒体凭证。

升级代码后，先检查 `render.yaml` 仍是免费规格，手动同步 Blueprint，再手动部署最新提交。默认关闭自动部署，避免未检查的改动直接影响朋友正在看的房间。

## 直连与免费额度

1—3 人在线时优先 P2P，4—8 人或直连失败时使用 LiveKit。直连时房主给每位朋友各上传一路，上传带宽不足不一定比转发更好。直连可能向已批准成员暴露公网地址；介意时在开始前选择“改用转发”。

成功直连不使用 LiveKit 参与者分钟或媒体下行额度，但控制服务仍需在线。转发会消耗自己的 LiveKit 额度；Render 免费服务也可能休眠或因额度暂停。不要承诺“无限永久免费”或把 Fork 本身当作免费云资源。详见[混合媒体](HYBRID_MEDIA.md)、[免费部署限制](FREE_HOSTING.md)。

## 常见问题

| 现象 | 下一步 |
| --- | --- |
| 网页很久才出现 | 免费实例可能正在唤醒，稍后重试；不要用保活脚本规避休眠规则 |
| 邀请失效 | 请房主重新生成完整邀请；需再次批准 |
| 有聊天但没有画面 | 确认房主已放映、自己点过观看，检查具体媒体状态；可由房主改用转发 |
| “媒体服务暂不可用” | 部署者检查 LiveKit 服务、WSS、密钥及免费额度，文件不需要重新上传 |
| 房主刷新后影片丢失 | 重新选择本地文件并确认续播；浏览器不会自动恢复文件权限 |
| 麦克风没声音 | 检查浏览器权限和输入设备，用设置里的主动检测；切换媒体路线后需重新开启 |
| 构建找不到 Vite 或类型定义 | 构建安装要包含开发依赖；Blueprint 已配置 `npm ci --include=dev`，构建后再 prune |
| 某视频网站不同步 | 此功能仍是实验性，先阅读[扩展使用说明](WEBSITE_WATCH.md)，各自需要正常观看权限 |

反馈问题时提供浏览器/系统版本、直连或转发、复现步骤和已隐藏私人信息的错误截图。不要提交影片、邀请令牌、会话 Cookie、媒体凭证、密钥或私人聊天。
